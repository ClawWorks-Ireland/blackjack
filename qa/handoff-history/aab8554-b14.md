## B14 (Low): count drill timing breaks in a background tab
- Repro: open Drills (W) → Count drill, 52 cards at 0.5 s, Start, then switch to another tab or window for a while and come back.
- Actual: the drill uses setInterval (app.js, cdTimer = setInterval(show, every)). Chrome throttles timers in hidden tabs to about one tick per second or slower, so the cards crawl. In live play in an attached Chrome tab, only 11 of 52 cards had been shown after about 2 minutes, and a later run scored "243.0 s, a pace of 243.0 s per deck". The elapsed time (Date.now() − cdStartedAt) is scored as the player's pace. In a visible tab the same drill is correct: 52 cards, count 0, 26.4 s.
- Expected: when the tab is hidden (document.visibilitychange → hidden), pause the drill: stop the interval, keep the current card, and show "Paused, come back to continue". Resume on visible. Subtract the paused time from the score. If you'd rather not resume, abandon the run and say "Drill stopped: the tab was hidden", and don't score it.
- Also: drive the card timing from the time elapsed since start (each card's due time = start + i × every), not from counting interval ticks, so a late tick can't stretch the drill while the tab is visible.
- Tests (DOM-free if you pull the scheduler into drill.js): a run with a simulated 60 s hidden gap reports the same time as one without it; a run hidden for longer than N seconds is either resumed with the pause excluded or not scored.
