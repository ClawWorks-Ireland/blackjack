# B109 (#178) AC7: how often does the old AC4 strategy end broke or stall?

Slice 5 (#232). Spec AC7 asks whether the `e66916e` AC4 failure (`no-report`) was
chips running out, from at least 20 runs of the old strategy. That failure was
`HARNESS Error: no shoe report appeared (AC4)`. No browser is needed:
`qa/lib/b109-ac4-rate.test.js` runs the strategy through `qa/lib/reach.js` on the
engine `Game` the page builds (start $1,000, table $1-$500, one deck), 200 seeded
trials per variant (`b109-ac7-<trial>-t<table>`), so every run gives the same numbers.

Reproduce: `node --test qa/lib/b109-ac4-rate.test.js` (Node v22.22.1). Output:

```
# {"variant":"old-ac4","trials":200,"ok":133,"broke":57,"noReport":10,"stalled":10,"node":"v22.22.1"}
# {"variant":"old-ac4-exact","trials":200,"ok":140,"broke":60,"noReport":0,"stalled":0,"node":"v22.22.1"}
# {"variant":"ac4-as-merged","trials":200,"ok":187,"broke":0,"noReport":13,"stalled":13,"meanTablesOk":1.6737967914438503,"node":"v22.22.1"}
```

- `old-ac4`: bankroll read digits-only (`$127.50` reads as 12750), bet `min(255, bankroll)`, one table, 80 rounds.
- `old-ac4-exact`: same strategy, exact bankroll, whole-dollar bets.
- `ac4-as-merged`: AC4 as merged in `3d6d122`: digits-only read, `minBankroll: 251`, up to 10 tables of 40 rounds.

## Answer to AC7

The `e66916e` failure is consistent with **both** causes, so neither can be ruled out
from its output alone.

- **Chips running out:** 57 of 200 `old-ac4` trials ended `broke` (28.5%). With exact
  reading it is 60 of 200 (30%), so this is plain chip loss: a $255 flat bet on a
  $1,000 bankroll with one table and no way to recover. A single AC4 run fails this way about 3 times in 10.
- **Bankroll misread:** 10 of 200 `old-ac4` trials (5%) hit a bet the table rejects
  (a cents bankroll after a 3:2 win reads as 100 times too big) and dealt nothing. The
  bankroll then stays frozen until the table runs out its rounds, which ends
  `no-report`, a false "game defect". The two counts match (10 stalled, 10
  `no-report`). `old-ac4-exact` has 0 of either, so the
  misread alone causes them.
- `ac4-as-merged`: no `broke` (more tables, a $251 floor), but 13 of 200 (6.5%) still
  `no-report` from the same misread. The `ok` trials needed 1.67 tables on average.

This is a rate, not a replay: the seed of the `e66916e` run was random and its output
had no detail, so we can't say which cause hit it. Both are real. Slice 6 (#233)
fixes the bankroll reading; the chip-loss `broke` end needs the strategy or the
retry-on-fresh-table logic, which the merged script already has.
